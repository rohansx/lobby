How it works

  1. You build the account in your own product, with their data already in it, under a placeholder email.
  2. You create a claim in Lobby with your product's id for that account. Lobby gives you a link.
  3. The prospect opens the link and enters their email. Lobby sends one confirmation email.
  4. The confirmation link sends them to your waitlist's Invite URL (or its Site URL) with ?claim=<code> added.
  5. Your app redeems the code from its server. Lobby answers with your account id and the verified email. Your app swaps in the email and logs them in.

Lobby never sees your product's passwords or sessions. It only proves that this email may take this account.

Creating a claim

On the project's Claims page, choose New claim. Or from code or the CLI:

curl -X POST https://trylobby.app/v1/claims \
  -H "Authorization: Bearer sk_…" -H "Content-Type: application/json" \
  -d '{"account_ref": "acct_123", "label": "Priya at Acme", "email": "priya@acme.com"}'

lobby claim create --ref acct_123 --label "Priya at Acme"
  • account_ref is required: your product's id for the account, up to 200 characters.
  • email is optional. With it, only that address can claim the account. Without it, whoever has the link claims it with their own address. Either way the email is confirmed first.
  • label is optional and shows on the claim page: "Acme set up an account for Priya at Acme".
  • expires_in is optional, in seconds. Links last 30 days by default.

A new claim for the same account_ref revokes the open one, so only the newest link works.

Redeeming in your app

On the page at your Invite URL, when ?claim= is present, redeem it from your server with the secret key:

const res = await fetch("https://trylobby.app/v1/claims/redeem", {
  method: "POST",
  headers: { Authorization: `Bearer ${process.env.LOBBY_SECRET_KEY}`, "Content-Type": "application/json" },
  body: JSON.stringify({ code: req.query.claim }),
})
if (!res.ok) return showLinkExpired()
const { account_ref, email } = await res.json()
await db.accounts.update(account_ref, { email })
await startSession(account_ref)   // then ask them to set a password

Codes work once and last 15 minutes. A 404 means the code is invalid, used or expired. The response also has label, claim_id, signup_id and a reporter_token for the feedback widget.

Tracking claims

The Claims page and GET /v1/claims show each claim's state:

StateMeaning
openCreated. Shown as "Sent" in the dashboard.
openedThe prospect has visited the link.
verifiedThey confirmed their email but your app hasn't redeemed the code yet.
claimedYour app redeemed the code.
revoked, expiredThe link no longer works.

Revoke from the dashboard, with DELETE /v1/claims/{id} or lobby claim revoke ID. The claim.opened and claim.claimed webhooks tell your CRM or Slack when it happens.

A claimed prospect joins your waitlist as joined, with source claim. They never get waitlist or launch emails, and you can give them the feedback widget.
