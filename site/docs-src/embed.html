Script widget

A form inside a shadow DOM, so your page's CSS can't break it and it can't break your page. It's under 2 KB gzipped.

<div id="waitlist"></div>
<script defer src="https://trylobby.app/v1/wl.js"
  data-project="pk_…" data-target="#waitlist" data-counter></script>

Without data-target, the form appears right after the script tag. The widget reads ?ref= and UTM tags from the page's URL and sends them along, so referrals and campaigns are tracked with no extra work.

Options

AttributeDefaultWhat it does
data-projectrequiredThe project's public key.
data-targetafter the scriptCSS selector of the element to render into.
data-buttonJoin the waitlistButton label.
data-placeholderyou@example.comEmail field placeholder.
data-successCheck your inbox…Message shown after signup when double opt-in is on.
data-counteroffShows "1,204 people are already waiting" once the list passes the project's counter floor.

Styling

Set CSS variables on the container to match your page:

#waitlist {
  --wl-accent: #2f6fd6;      /* button background */
  --wl-accent-ink: #fff;     /* button text */
  --wl-bg: #fff;             /* input background */
  --wl-ink: #1f1c17;         /* input text */
  --wl-border: #e9e5dd;
  --wl-radius: 999px;
  --wl-pad: 12px 18px;
  --wl-muted: #7a746a;       /* messages */
  --wl-error: #b42318;
}

For anything the variables don't cover, style the parts directly: #waitlist::part(form), ::part(input), ::part(button) and ::part(message).

Listening for signups

The widget fires a lobby:signup event that bubbles up from the container. Hook your analytics into it:

document.addEventListener("lobby:signup", (e) => {
  plausible("Waitlist signup")
  console.log(e.detail) // { ok, confirm_required, message, position?, referral_link? }
})

Plain HTML form

No JavaScript at all, which suits static sites and site builders. After submitting, the person sees your project's thanks page, or the page set in Settings → Redirect after signup.

<form method="post" action="https://trylobby.app/v1/w/pk_…/signup">
  <input type="email" name="email" required>
  <!-- a honeypot: people never see it, bots fill it in -->
  <input type="text" name="website" tabindex="-1" autocomplete="off"
    style="position:absolute;left:-9999px">
  <button>Join the waitlist</button>
</form>

Add a hidden _redirect field to send people to a specific page instead. It must be on your site URL, an allowed origin, or the page the form was on.

Hosted page

Every project has a page at https://trylobby.app/w/your-slug with the headline, description and consent text from its settings. Use it when you don't have a site yet, or link to it from social posts. It works without JavaScript.

From your own code

Building a custom form in React, Svelte or a mobile app? Post to the signup endpoint and ask for JSON:

const res = await fetch("https://trylobby.app/v1/w/pk_…/signup", {
  method: "POST",
  headers: { "Content-Type": "application/json", Accept: "application/json" },
  body: JSON.stringify({
    email,
    ref: new URLSearchParams(location.search).get("ref") ?? "",
    source_url: location.href,
  }),
})
const data = await res.json()

Accepted fields: email (required), ref, source_url, referrer, utm_source, utm_medium, utm_campaign, utm_term and utm_content. JSON, URL-encoded and multipart bodies all work.

With double opt-in on (the default), the answer is always the same, whether the address is new, already on the list, or flagged as spam. That way the endpoint never tells a stranger who's on your list:

{ "ok": true, "confirm_required": true, "message": "Check your inbox. We've sent you a link to your spot." }

With double opt-in off, a new signup gets its place straight away:

{
  "ok": true, "confirm_required": false, "message": "You're on the list.",
  "position": 1205, "behind": 0,
  "status_url": "https://trylobby.app/s/…",
  "referral_link": "https://orbit.app/?ref=k3x9q2"
}

Errors come back as {"ok": false, "error": "…"} with a 4xx status, and the message is written to show to the person as is. Too many attempts from one address returns 429.

Allowed origins

In Settings → Allowed origins, list the sites that may post to this waitlist, one per line, such as https://orbit.app. Browsers on any other site are refused. With the list empty, any site can post, which is handy while testing but worth closing before launch.

Spam protection

Every way in gets the same checks, with no CAPTCHA:

  • a honeypot field that people never see,
  • a timing check: forms submitted faster than a person could type are dropped,
  • rate limits per IP address and project,
  • a list of disposable email domains,
  • an MX lookup to confirm the domain can receive mail.

Spam gets the same "check your inbox" answer as a real signup, so bots can't tell they were caught.
