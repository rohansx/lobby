Run it with Docker

docker run -d --name lobby -p 8080:8080 -v lobby-data:/data \
  -e LOBBY_BASE_URL=https://wait.example.com \
  -e RESEND_API_KEY=re_… -e LOBBY_FROM_EMAIL=waitlist@mail.example.com \
  ghcr.io/rohansx/lobby:latest

Open the address in a browser. The first visit asks you to create the admin account; after that, sign-up is closed. Put it behind your reverse proxy (Caddy, Traefik, nginx) for HTTPS.

The image is built for amd64 and arm64, and answers GET /healthz for health checks.

Docker Compose

git clone https://github.com/rohansx/lobby && cd lobby
LOBBY_BASE_URL=https://wait.example.com RESEND_API_KEY=re_… \
LOBBY_FROM_EMAIL=waitlist@mail.example.com docker compose up -d

Dokploy, Coolify and other PaaS

Deploy the image, mount a volume at /data, and set LOBBY_BASE_URL to the public address. The repository's blueprints/lobby/ folder has a docker-compose.yml and template.toml for a Dokploy template.

From source

Needs Go 1.26 and Node 24.

(cd web && npm ci && npm run build)   # builds the dashboard into the binary
go build -o lobby ./cmd/lobby
LOBBY_BASE_URL=https://wait.example.com ./lobby serve

Configuration

Everything is set with environment variables. Per-project settings live in the dashboard.

VariablePurpose
LOBBY_BASE_URLPublic URL of the instance. Links in emails and snippets use it, so get this one right.
LOBBY_FROM_EMAILSender address, ideally on a sending subdomain (waitlist@mail.example.com).
RESEND_API_KEYSend email with Resend.
SMTP_URLOr any SMTP server: smtp://user:pass@host:587 or smtps://user:pass@host:465.
RESEND_WEBHOOK_SECRETVerifies Resend's bounce and complaint webhook at /v1/hooks/resend.
LITESTREAM_REPLICA_URLContinuous backup target, for example s3://bucket/lobby. See below.
LOBBY_DATAData directory. /data in the image, ./data otherwise.
LOBBY_ADDRListen address, default :8080.
LOBBY_TRUST_PROXYSet to 0 if Lobby faces the internet directly rather than behind a proxy, so it ignores X-Forwarded-For.
LOBBY_CHECK_MXSet to 0 to skip the MX lookup on signup.
GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET"Continue with Google" for the admin. Redirect URI: {LOBBY_BASE_URL}/auth/google/callback.
GITHUB_CLIENT_ID, GITHUB_CLIENT_SECRET"Continue with GitHub" for the admin. Callback URL: {LOBBY_BASE_URL}/auth/github/callback.

Without RESEND_API_KEY or SMTP_URL, emails are written to the log instead of sent. Set up your sending domain before launch: see deliverability.

Backups

The image includes Litestream. Set these and every change to the database is copied to S3-compatible storage within seconds:

LITESTREAM_REPLICA_URL=s3://my-bucket/lobby
LITESTREAM_ACCESS_KEY_ID=…
LITESTREAM_SECRET_ACCESS_KEY=…

When the container starts with an empty volume and a backup exists, Lobby restores it first. So moving to a new server is: start the container there with the same variables.

Works with AWS S3, Cloudflare R2, Backblaze B2, Tigris and MinIO. For storage other than AWS, add the endpoint to the URL, for example s3://my-bucket/lobby?endpoint=https://ACCOUNT_ID.r2.cloudflarestorage.com.

Not using Litestream? Copy /data/lobby.db with sqlite3 /data/lobby.db ".backup backup.db", not a plain file copy, so the copy is consistent.

Upgrading

docker pull ghcr.io/rohansx/lobby:latest
docker rm -f lobby && docker run -d … ghcr.io/rohansx/lobby:latest   # same flags as before

Database migrations run on start. Take a backup first if you're not using Litestream.

Running a hosted service

LOBBY_CLOUD=1 turns an instance into a multi-tenant service, which is how Lobby Cloud runs: anyone can sign up, each account sees only its own waitlists, and plan limits and billing through Polar apply. The full list of variables is in the README. You don't need any of it to run Lobby for yourself.
