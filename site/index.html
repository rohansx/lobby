For your prospects

One link, their own email

They open the link, confirm their address and land in an account that's already theirs. Your product makes one API call to finish the handover.

  • The email is verified before anything changes hands
  • Lock a claim to one address, or leave it open to whoever holds the link
  • See when a prospect opened their link
  • Links expire after 30 days and can be revoked
claim.ts
// 1. Create a claim for an account you built
// lobby claim create --ref acct_123
//   → https://trylobby.app/c/9f2k…

// 2. They confirm their email, then arrive at
//    your app with ?claim=<code>
const res = await fetch(
  "https://trylobby.app/v1/claims/redeem", {
    method: "POST",
    headers: { Authorization: "Bearer sk_…" },
    body: JSON.stringify({ code }),
  })
const { account_ref, email } = await res.json()

// 3. The account is theirs
await accounts.update(account_ref, { email })
Feedback New

Your first users find the bugs. Lobby brings them to you.

The people you invite get a small Feedback button inside your app. They click the thing that's wrong and say why. Lobby groups the reports into issues, and emails everyone who reported one when you mark it fixed.

For the people you let in

Click the element, say what's wrong

A report is a bug, something confusing or an idea, pinned to one element on one page. It arrives with what you need to reproduce it.

  • A screenshot of the picked area, with the element outlined
  • Their last few clicks and page changes, never what they typed
  • The element's state: disabled, loading, empty or cut off
  • Speak instead of typing, in English or any Indian language

Twenty reports, one issue

Reports on the same element land in one issue. Claude writes a clear title and a short summary, suggests duplicates for you to merge, and can ask the reporter one question when a report is vague.

Hand issues to your coding agent

Approve an issue and it becomes a work packet: the selector, page context, screenshot and what people said. An agent key can read approved issues and post notes, and nothing else.

You choose who sees it

Everyone you've invited, only the people you switch on, or testers you add by email who never joined the waitlist. A weekly digest tells you what to look at first.

Self-host

Prefer your own server? It's one container.

The same Lobby that runs Cloud, MIT licensed, with no limits: one binary and one SQLite file in about 20 MB of memory. Start the container, create your admin account, paste a snippet onto your site. Self-hosting guide.

Docker

Multi-arch (amd64 and arm64), with Litestream built in for backups.

docker run -d -p 8080:8080 \
  -v lobby-data:/data \
  -e LOBBY_BASE_URL=$URL \
  -e RESEND_API_KEY=re_… \
  ghcr.io/rohansx/lobby

Dokploy, Coolify, any VPS

Point your PaaS at the image or the repo, mount a volume at /data and set the public URL.

git clone \
  https://github.com/rohansx/lobby
cd lobby
LOBBY_BASE_URL=$URL \
  docker compose up -d

FAQ

Questions, answered.

Something else? Read the docs or open an issue.

Is it really free?

Self-hosted, yes. Lobby is MIT licensed with no signup limits and no phone-home. You pay for the server it runs on and for your email provider, and Resend's free tier is enough for a small launch. Rather not run a server? Lobby Cloud is free up to 500 signups.

How do early users report problems?

Add one script tag to your app for logged-in users. People you've invited, or testers you add by email, get a Feedback button: they click an element and say what's wrong. Reports are grouped into issues in your dashboard, and reporters get an email when you mark an issue fixed. The integration guide is written so you can hand it to a coding agent.

What does Lobby use AI for?

Only feedback. Claude titles and summarizes issues, suggests duplicates, may ask a reporter one follow-up question and writes an overview in the weekly digest. Nothing merges or changes state by itself, and you can switch it off per waitlist. Self-hosted, it stays off unless you set ANTHROPIC_API_KEY.

Is Lobby just a waitlist?

It started as one. Today it also runs in-app feedback from the people you let in, and ready-made accounts your prospects can claim. Launching to every platform from one profile is in early access with Lobby Pro. Use one part or all of them.

What do I need to run it?

Anything that runs a Docker container: a small VPS, Dokploy, Coolify, Fly.io or Railway. It idles at about 20 MB of memory. Mount a volume at /data so your list survives restarts.

Can I run waitlists for several products?

Yes. Each project has its own form, keys, allowed origins, emails, referral rules and settings, and they all share one dashboard.

How do I stop people gaming referrals?

A referral only counts after the friend confirms their email, credits are capped per IP address and per hour, and addresses are normalized so Gmail dots and +tags can't create duplicates. Disposable domains are rejected.

What about backups?

Set LITESTREAM_REPLICA_URL to any S3-compatible bucket and the database is replicated continuously. On an empty volume Lobby restores from the replica automatically.

How do I let people in when I launch?

Click Invite the next wave in the dashboard or run lobby invite --next 50. Each person gets a magic link and a code. Your product calls POST /v1/invites/redeem, or you send a launch broadcast to everyone at once.
